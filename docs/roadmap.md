# Roadmap

## Current documentation scaffold

- Project overview, ownership requirement and local asset policy.
- Planned setup and architecture notes.
- Contribution templates and a public-content check.

## Before a public playable preview

- Prepare portable runtime source and choose its code license.
- Implement the local game-file validation and extraction/decoding workflow.
- Audit dependencies, notices and publication contents.
- Document a clean installation on a machine without the development workspace.
- Package original project code without original game data or generated asset caches.

## Continue desktop development

- Polish chamber scale, visibility and area-entry stalls.
- Improve combat readability while preserving original rules.
- Validate the remaining encounters, Queen, ending and full-game navigation.
- Test physical controllers and fresh-install save/Continue/retry paths.

The local 0.11 prototype has a reviewed route through 35 original Metroid defeats. That does not mean the full game or a public download is ready.

## Later

Revisit Switch homebrew packaging and performance after the desktop experience is stable. No release date or Switch frame-rate promise is set.
